## Turn and auction race assessment

`advanceTurn(expectTurn)` validates live turn, playing phase, and absence of an auction (`useGameLogic.ts:313–318`). Timer, auto-advance and End Turn use this turn number, so sequential duplicate calls for a completed turn normally become no-ops. Core settles rent/card before advancing (`core.ts:37–57`); purchase/card/auction can also advance directly. Their idempotence is uneven: purchase requires pending offer and property, auction checks only whether *some* auction is present, card fallback advances without its original card. Jail acts on currentPlayer without expected identity. An old timeout reads a refreshed callback ref; bot End Turn invokes the latest expected turn, so guarding only that freshly captured turn does not establish that the delayed bot intent still belongs to it. Bind intent at scheduling time.

Turn expiry compares a captured endAt and validates only turn number inside the updater. A roll resets the deadline without incrementing turn; an already submitted expiry can consequently advance a freshly rolled turn. Validate expected deadline as well as turn. With timer off, disconnection has no turn fallback; the 2s completed driver is current-player-only.

Auction low-bid races are correctly rejected against live currentBid; late bid extends to at least 15s. Unaffordable/inactive winner leaves property unsold. Disconnect does not invalidate a bidder's accepted bid; remaining clients resolve it. Draft queue removes an item before auction starts, so unsold items are not retried; 0/1/many progress correctly while driver exists. A property already owned cannot normally start auction or trade while isInAuction; property editor can still overwrite flags/prices during play without phase/host validation. Seller payout occurs on resolution except when seller is bidder (bidder branch returns first); UI prevents seller bids, hook doesn't. Auctions-off draft is not explicitly blocked. All timing uses client Date.now without offset estimation; the 1s/1.5s tolerances do not solve large skew. Entire-room writes and every-client resolution amplify contention; no 8-player emulator load test was run.
